# 最后的岛 · 垂直切片

这一版只验证一件事：**能不能连着看 30 分钟，并且看到一个没有预设过的故事。**

## 运行

```bash
cd world/prototype
node server.js
```

打开 http://localhost:4173

不需要 `npm install`，没有任何依赖。

`?static=1` 只拉一次状态、不接实时流，方便截图和离线调试；`?mode=island` 直接打开全岛总览，`?select=a1` 直接跟随某个人。

## 它现在有什么

- 一张 40×40 的岛：水、草地、树、灌木、岩石、无法辨认的残骸。
- 十二个人，每个人有出身、执念、禀赋、旧伤。他们不知道自己为什么在这里。
- 确定性引擎：饥饿、体力、采集、建造、战斗、死亡全部由代码计算。
- 规则大脑：不配置任何 API 也能跑，所有人按本能活着。
- LLM 大脑：配置 API 后，前 N 个人改成由语言模型决定下一步，引擎只负责判定结果。
- 感知：每个人有朝向。白天看得见 6 格、夜里 3 格，120° 视野，树/岩石/墙会挡住视线；声音（打斗、惨叫、说话、敲打、狼嚎）能穿墙，但只给方向和模糊距离，不会告诉你名字。地图上的小圆点旁边有一条短线，就是他的朝向。
- 昼夜与野兽：天黑后有 1–3 头野兽出现，靠近火堆才安全。
- 营地：第一堆火会成为一个永久营地。之后的夜里，人们会向它聚集；营地烧完后，第二天会有人回来重新点火。
- 资源的循环：灌木约 1.5 个世界日长回来，树约 4 天。**人死后，坟边的土会变肥，两三天后长出灌木。**
- 渔与耕：站在水边可以捕鱼（鱼是无限的）；花 1 份食物可以在草地上种一丛灌木，两天后长出来。
- 写信：选中一个已经进入收养/收徒关系链的人，以祖先的声音给他写一句话。他会读到它；没有关系链的人只听见一个听不懂的声音。
- 死亡是永久的：死去的人会在原地留下一座坟。
- 事件日志与存档：每次事件带连续序号只追加；每 10 秒写一份快照；重启时从快照恢复，按离线时间快进，并给出“你不在时”的关键事件摘要。离线推进默认最多补 7 个世界日（`OFFLINE_MAX_DAYS` 可调），超出部分只报告 `skippedTicks`。
- 事实与信念分层：引擎把发生过的事写进事实层；死亡的目击者会留下一条信念；交谈只有听得懂时才会留下内容，听不懂只留下“他说了一句听不懂的话”。两者分开保存。
- 记忆失真：转述时，谓词会沿受控词表升级（死 → 被人杀、说 → 威胁），数量、时间、地点和细节会按概率走样；漂移只写进听者的信念，事实层不动；每传一次，确信度下降，并记下是谁说的。亲眼看见被传死的人还活着，会推翻那条信念。观看者同时拿到事实与信念。
- 继承：可以收养或收徒；死后继承人得到物品、建筑、部分技能与信念，徒弟额外继承手艺知识，养子不继承；死者没做完的执念会跟着继承人走。没有继承人时留下无主遗产和空宅，别人可以搬进去。建筑归主人使用，别人在同一屋檐下休息拿不到额外的好处。没有生育。
- 脱变：引擎判定转折（杀人、仇人死亡、亲手埋葬收养或收徒的人、被信任的人背叛、被别人当成主心骨、杀死野兽），模型在受控词表里选一个身份标签；一生 2–5 次，每次写进编年史（带时间与地点），并改变身份与行为倾向（“手上带血的人”更敢动手，“独行者”不再主动搭话，“猎手”夜里更敢迎战野兽）。
- 语言墙：十二个人按同乡分说北岸话、南渡话、外来话三种语言；同语言的人能听懂，不同语言的人只听见声音（方向与模糊距离，不带名字），但观看者永远看得懂原话。相邻共处会慢慢学会对方的语言，也可以明确教；会两种语言的人能当桥梁。
- 制度：律法、教义、结社三张固定表，只能填槽；声望够高的人才能立。律法可以按地点、对象、是否持械、声望设条件；律法与教义对所有人生效，违反会被引擎判定并处罚。教义会传播给所有活着的人。结社有领袖、成员、加入条件与共同住处，领袖死后由声望最高的成员接手。制度的解释权由解释者之间的声望与结社力量决定：strict 严格执行，lenient 宽缓处理。
- 被惦记才清醒：被转述、被写信、被埋葬、被教学都会增加“被记住”的程度；死者也会因为被埋葬而被记住。每天衰减，归零后开始淡出，分三级，最后被世界抹去，不留坟。只要被提起一次，淡出阶段就会重置。
- 在线/睡眠轴：跟随一个人就是守望他。观看页面的心跳会让当前日志权威写一条 `presence` 租约：被守望的人醒着、不参与每日遗忘；心跳失效、租约过期或切走，就回到规则驾驶。`presence` 是事件日志的一部分，重放和追平后所有节点对“谁醒着”的判断一致。在线才会说话、离线只能由规则驾驶这一层行为差异还没做——它要等真人上传和模型归属。
- 上传一个人：点右上角「上传一个人」，填四字段（出身 / 执念 / 禀赋 / 旧伤）、一句口吻和一种语言，从雾里把一个人送上岛。出身 / 禀赋 / 语言只接受受控词表；上传要算一次轻量 PoW；记录由本机节点 Ed25519 签名后写进 `arrival` 事件。上传所在节点不是权威时，会把签名记录转发给当前权威。表单明确提示日志不可删除，并拒绝网址、邮箱、账号和长串数字。限制是双层的：一个节点只能上传一次，同一个浏览器玩家 id 也只能上传一次。
- 浅睡：自己的居民可以买一个世界日的半离线保护。浅睡期间 `presence` 在线、不参与淡忘，但不受主人提案驱动（规则接手）；租约到期自动回到规则。v1 只实现机制，支付是外部闸门。
- 举报与导出：任何居民都可以本机举报（记录只保存在本机，供人工查看，不进共享日志）；编年史可以「导出这一版」成 Markdown；全岛面板新增「改变过的人」和「从雾里来的人」。
- 公开看台：`/public` 或 `/?public=1` 进入只读模式，隐藏暂停、倍速、上传、大脑、写信、浅睡和举报；右上角可以在中文/英文界面之间切换（`?lang=en`，会记住选择）。世界文本（居民对话、编年史、制度描述）仍是中文。
- 时间轴回到过去：选一个过去的第 N 天，`/api/history?day=N` 会从日志重放到那一天的 08:00，返回当时的地图、居民、建筑、野兽和制度；页面切到历史态（只读），点「今天」回到现在。历史快照按天缓存在进程里，世界整体重建时清空。
- 主人的模型：上传者所在的节点会替自己的居民提前算好下一步，签名后交给当前权威。权威重新做受控解析、排队，并在决策时写 `source: owner`；提案顺带续上清醒租约。主人在线但这一拍没有提案时，居民会发呆等待（决策日志里是 `source: owner-wait`），不退回规则；主人租约过期后才重新由规则接手。只有 `arrivedBy` 等于该节点的居民能被它驱动。
- 知识分层：出身决定初始技能（教师会教、农妇会种、铁匠会造、猎人会打）；生火是生存常识，搭窝棚、砌墙、捕鱼、耕种、削武器来自出身，不会的人必须向别人学；学知识要上几节课，进度由禀赋决定；做一件事会涨对应技能，成长速度也由禀赋决定；相邻的人会互相教，知识和技能沿着关系流动。
- 编年史叙事：引擎只挑关键事件（死亡、脱变、立法、结社、冲突、迁移、收养/继承、淡出）；每个观看者用自己的模型写自己的版本，叙事按「观看者 + 事件段」缓存，不进存档，所以没有官方历史。不配置模型时用本地叙事器，事件照样读得通。缓存会写到本机 `narratives-<节点名>.json`，重启后同一段事实不必重新调用模型；它不跨节点同步。
- 观看界面 v1：重新打开先看到「你不在的时候」；跟随一个人时能看他的师承与继承人、事实 / 他自己的看法 / 个人史三栏，以及「被记住」和淡出进度；全岛模式看人口、语言、制度与最近编年史；底部时间轴可以回到任意一个世界日，点开就是那天的编年史。写信后有冷却。
- `node test-sim.js`：不启动网页，直接让引擎跑 2.5 个世界日，检查死亡、建造、冲突的分布。
- `npm test`：136 个测试，覆盖地基、知识分层、记忆失真、继承、脱变、语言墙、制度、淡出、编年史、同步日志、节点身份、在线/睡眠轴、浅睡、上传、举报、主人提案、编年史导出、网络分区与 HTTPS。除既有系统外，新增 Ed25519 信封签名与身份自证、TOFU 信任表、请求防重放、在线租约与确定性重放、浅睡租约、上传的受控字段/PoW/签名/玩家级一次性、举报计数、主人提案的归属校验与决策重放、分区愈合与人工对账、TLS 双节点收敛。

## 它还没有什么

- 自动分区合并与拜占庭容错（B 阶段后续）：当前只做诚实节点的宕机/恢复、签名校验与确定性收敛；分区愈合仍有损，见下文。
- 浅睡只实现了机制，没有真实收费；举报只存在本机，没有审核流程；“在线才说话、离线是哑者”的完整行为差异也还没分开。主人租约到期后仍会退回规则（`OWNER_LEASE_TICKS` 默认 60）。
- 英文只翻译界面外壳；居民对话、编年史叙事、制度描述和世界文本仍是中文。真正的双语世界需要语言生成层，而不只是 UI 字典。
- 上传的“一次”是按节点算的，不是按人；节点换密钥就能再上传。隐私红线是正则过滤（网址 / 邮箱 / 账号 / 长数字），不是人工审核，也没有举报入口；PoW 只能抬高刷量成本。
- 首次信任仍是 TOFU，不防首次 MITM；公网部署需要 TLS（已可配置并有端到端测试）加带外公钥核对。
- 历史态每次按天从日志重放，快照只缓存在当前进程里；长日志或很远的过去会慢，重启后重新计算，也不跨节点共享。
- 叙事缓存只保存在本机（`narratives-<节点名>.json`），不跨节点同步；换节点或换观看者会重新生成。

## B 阶段地基：同步日志

> 主路径是 `SYNC_MODE=peer`：全节点、双向拉日志、按事件数轮换日志权威。
> 单主 → 镜像（`MIRROR=1`）只作为演示 / 回归模式保留。约束见 [../06-架构-B阶段.md](../06-架构-B阶段.md)。

`sync.js` 把事件日志变成可交换的权威输入；`server.js` 提供两种传输适配器：

- **导出**：`exportJournal(world)` 生成带种子、序号范围、事件、决策、事件哈希、决策哈希与状态哈希的信封；`fromSeq`/`prevHash` 可切块并串成链。
- **校验**：`verifyJournal` 检查协议、序号连续、事件哈希、以及决策必须确实是事件的投影；`verifyChain` 检查两块日志首尾相接。
- **重建**：`rebuildFromJournal` 从种子 + 完整日志逐字节重放回同一个世界；`stateHash` 只覆盖会影响下一步模拟的状态，界面日志、暂停/倍速、API 配置都不算。脱变标签也以日志里的为准，LLM 选过的身份不会在重放时退回确定性标签。
- **追平**：`applyChunk(localSnapshot, chunk)` 从本地快照 + 对方的一块后续日志追到同一个世界；`catchUp(localWorld, fullJournal)` 用完整日志从零重建。追平后的世界会退出重放模式，可以继续做新决定。
- **块尾收尾**：一块日志的最后一条可能是 `term` / `presence` / `arrival`，它要等下一次写事件才会插回。`applyChunk` 在比较 `stateHash` 前先收尾插入，否则“只有一条非决策事件”的块永远对不上——这个 bug 是在做主人提案时被两节点测试抓出来的。
- **peer 轮值**：每个节点都从对端拉缺失日志块；`term = floor((nextSeq - 1) / TERM_EVENTS)`，`authority = 排序后的节点列表[term % 节点数]`。同一时刻只有当前权威推进模拟，其他节点只读、追平。交接时新权威先拉完日志、等 `HANDOFF_SETTLE_MS` 再写。
- **故障交接**：当前权威失联超过 `TAKEOVER_MS`，轮值里的下一个节点把“第几任、谁是权威”写成一条 `term` 事件追加进日志，直接接任；再下一个节点多等一个 `TAKEOVER_MS`，给更近的节点留窗口。接管记录本身是日志的一部分，所以所有节点从同一条日志解出同一个任期，不依赖墙钟排序。旧权威带着旧存档回来时会读到更高任期，先追平再作为跟随者参与，不会重新夺权。
- **旧尾巴**：如果回归的旧权威存档比幸存者更新（它失联前最后几条事件没被任何人拉到），以更高任期为准：用幸存者的完整日志重建，丢弃这段旧任期尾巴。只有“同一任期内”的分叉才记 `syncFault` 并停写。
- **人工出口**：`POST /api/sync/adopt`（带 `SYNC_TOKEN`，body `{"peer":"http://..."}`）用指定对端的完整日志重建本地世界，用于处理无法自动收敛的分叉。
- **分叉处理**：同一头部却 `stateHash` 不同、或重叠事件不一致时，节点记录 `syncFault` 并停止写入，不静默采用对方状态。
- **身份与签名**：每个节点首次启动生成 Ed25519 密钥对，写在 `NODE_KEY_FILE`（默认 `node-key-<节点名>.json`），私钥不进存档、不进日志。`/api/journal` 的每个信封都带签名；`/api/identity` 的身份声明由本节点自证。对端第一次接触时把公钥固定进 `TRUST_FILE`（默认 `trusted-peers-<节点名>.json`），之后换钥匙一律拒绝。一个地址换了 `nodeId` 也会被拒绝。
- **鉴权**：`/api/journal/apply` 与 `/api/sync/adopt` 接受 `SYNC_TOKEN` bearer token **或**节点签名。签名请求带 `x-node-timestamp` / `x-node-nonce` / `x-node-signature`，服务端先验签、再用 nonce 防重放（默认 60 秒时钟窗口、5 分钟 nonce 生命周期）。日志信封的签名者必须与请求签名者是同一个节点。peer 模式默认用拉取，不需要对端开放写入。状态页显示节点角色、任期、交接状态和同步错误。

### 全节点轮值（主路径）

两台机器用同一个 seed、同一份节点名单和强随机 token；`PEERS` 互相指向对方：

```bash
# A 机（本机可直接用不同 PORT 模拟两台）
NODE_ID=peer-a SEED=20261102 PORT=4173 \
SYNC_MODE=peer NODES=peer-a,peer-b PEERS='http://B机局域网地址:4173' \
SYNC_TOKEN='替换成随机长 token' TERM_EVENTS=200 \
node server.js

# B 机
NODE_ID=peer-b SEED=20261102 PORT=4173 \
SYNC_MODE=peer NODES=peer-a,peer-b PEERS='http://A机局域网地址:4173' \
SYNC_TOKEN='替换成随机长 token' TERM_EVENTS=200 \
node server.js
```

`TERM_EVENTS` 越小，轮换越频繁；默认 200。`LEASE_MS`（默认 6000）是“多久没听到对方”的判定尺度；`TAKEOVER_MS`（默认 `2×LEASE_MS`）是接任前的等待。查看 `/api/identity` 能看到 `role`、`term`、`termSource`、`authorityId`、`successorId`、`handoffReady`、`takeoverEtaMs`、`lastTakeoverAt`、`syncFault`、`keyId`、`publicKey` 和每个对端的 `peerHealth`。

身份相关的可调项：

- `NODE_KEY_FILE`：节点私钥文件，默认 `node-key-<NODE_ID>.json`。**不要提交、不要复制到别的机器**；重启必须复用同一文件，否则对端会拒绝新钥匙。换 `NODE_ID` 前先处理旧文件。
- `TRUST_FILE`：本机信任表，默认 `trusted-peers-<NODE_ID>.json`。删掉某个节点条目等于重新信任它的新公钥。
- `VERIFY_SIGNATURES=0`：关闭签名校验（只用于兼容旧节点或临时排障）。
- `NODE_CLOCK_SKEW_MS`（默认 60000）/ `REPLAY_TTL_MS`（默认 300000）：签名请求的时钟窗口与 nonce 保留时间。两台机器的时间要大致同步。
- `TLS_KEY_FILE` / `TLS_CERT_FILE`：同时配置后节点改用 HTTPS；对端 `PEERS` 也要写 `https://`。自签证书需要 `NODE_EXTRA_CA_CERTS` 或系统信任链，否则 fetch 会拒绝。

`sync-check.js` 也能验证来源：把节点公钥导出成 PEM（`/api/identity` 的 `publicKey` 字段）后运行 `node sync-check.js journal.json --pubkey node-a.pem`；签名不通过时退出码非零。

- `test-peer-rotation.js`：两个真实进程轮流担任权威，每个任期后状态哈希收敛。
- `test-peer-failover.js`：杀掉当前权威，验证幸存者按租约接任、世界继续推进；旧权威重启后收敛为跟随者。第二个用例制造“旧权威存档更新”的局面，验证按更高任期重建、丢弃旧尾巴且不报 `syncFault`。
- `test-partition.js`：用两个可切断的本地 TCP 代理夹住两个真实进程，断网后两边同时持有写入权；愈合后更高任期成为基准，旧权威丢掉分区期间的事件（`lastAdoption.dropped`），另一侧停写；人工 `/api/sync/adopt` 后恢复并继续推进。

**分区仍然是有损的**：如果旧权威没有死、只是和你网络断开，它会在自己那一侧继续写，而下一节点也会接任。愈合后以更高任期为准，旧权威分区期间写的事件会被丢弃，丢弃条数记录在 `lastAdoption.dropped`；更高任期一侧看到分叉会记录 `syncFault` 并停写，需要人工用 `/api/sync/adopt` 指定基准。v1 只保证诚实节点的宕机/恢复，不做拜占庭容错或自动分区合并。

### 两台机器验收

先按上面的方式启动 A、B，然后在一台机器上跑：

```bash
node peer-check.js http://A机地址:4173 http://B机地址:4173 --watch 30 --settle
```

它会检查身份自证、种子、互相固定的公钥、日志信封签名，并在观察窗口结束时暂停当前写入者、等跟随者追平后比较 `stateHash`。输出会列出任期/写入权的每一次变化；退出码 0 表示通过。

手动验收步骤：

1. **轮值**：`--watch` 至少看到一个 `peer-a / term N` 变成 `peer-b / term N+1`，结束时两边 `stateHash` 一致、没有 `syncFault`。
2. **杀权威**：直接 Ctrl-C 当前写入者；在幸存者上等 `TAKEOVER_MS`，看 `authorityId` 变成自己、`term` 增加、`tick` 继续推进。重启旧节点时要复用同一个 `NODE_KEY_FILE`，再跑一次 `peer-check`，确认 `keyId` 没变、它变成跟随者、`stateHash` 收敛。
3. **密钥没换**：如果看到 `node key mismatch`，说明节点换了密钥文件；恢复旧文件，或从 `TRUST_FILE` 里删掉该节点条目后重新固定。
4. **分区**：不要杀进程，用防火墙/断网切断一端，重复上面的观察；愈合后留意 `lastAdoption.dropped` 和 `syncFault`，按提示用 `/api/sync/adopt` 恢复。

### 镜像演示（旧脚手架）

镜像模式仍是单主 → 镜像，只用于演示和回归。A 的 `PEER_URL` 指向 B：

```bash
# A 机：主节点
NODE_ID=node-a SEED=20261102 PORT=4173 \
SYNC_TOKEN='替换成随机长 token' PEER_URL='http://B机局域网地址:4173' \
node server.js

# B 机：镜像节点
NODE_ID=node-b SEED=20261102 PORT=4173 MIRROR=1 \
SYNC_TOKEN='替换成随机长 token' SAVE_FILE='./world-save-mirror.json' \
node server.js
```

也可以手动导出/验证，或把日志拷到离线机器：

```bash
curl 'http://A机地址:4173/api/journal?nodeId=node-a' > journal.json
curl -X POST http://B机地址:4173/api/journal/verify \\
  -H 'Content-Type: application/json' --data-binary @journal.json
node sync-check.js journal.json
```

事件哈希（FNV-1a 64）只负责发现内容篡改；**来源与授权由 Ed25519 签名负责**。信封签名能证明“这段日志是某把私钥的持有者发的”，但首次接触仍是 TOFU：第一次看到的公钥会被直接固定，所以首次 MITM 仍可能成功。要跨不可信网络，必须同时开 TLS，并把节点公钥通过带外渠道（人工核对指纹）导入信任表。租约到期后的接任已经实现（`LEASE_MS` / `TAKEOVER_MS`）；自动分区合并与拜占庭容错仍未实现。

## 在线 / 睡眠轴

跟随时，网页每 5 秒给 `POST /api/presence` 发一次心跳：

```json
{ "viewerId": "本机 localStorage 里的随机 id", "agentId": "a3" }
```

- 当前日志权威会把活跃心跳翻译成日志里的 `presence` 事件：`{ agentId, online: true, untilTick, by, reason }`。被守望的人 `presence = 'online'`，不参与每日遗忘；租约到期或心跳消失后写 `online: false`，回到规则驾驶。
- 切到全岛、隐藏页面、关闭页面时会发 `agentId: null`，权威立刻让人睡回去。
- 观看者挂在跟随节点时，节点会把守望通过 `/api/presence/forward` 转发给当前权威，权威按 `${nodeId}:${viewerId}` 记住它并写 `presence`；心跳停止、切走或节点掉线后由 TTL 清理。这样任何人连自己的节点都能守望。
- 所有 `presence` 事件都进日志，重放、追平、重建后所有节点对“谁醒着”的判断一致；`stateHash` 覆盖 `presence` 与 `presenceUntil`。
- `TENDER_TTL_MS`（默认 15000）：心跳多久没来算失效。
- `PRESENCE_LEASE_TICKS`（默认 300）：写进日志的清醒租约，1 tick = 1 世界分钟；默认约现实 12.5 秒。续期在租约过半时发生。

页面上的状态：跟随面板会显示「醒着 · 有人守着」或「睡着 · 本能」；「被记住」一行会说明是否因为有人守着而不会淡出。

## 上传 / `arrival`

新居民唯一的入口是 `arrival` 事件，没有“创建 API”之外的旁路。

```http
GET  /api/arrival     → { difficulty, origins, aptitudes, languages, limits, notice }
POST /api/arrival     { core: {...}, pow: { nonce, difficulty } }
```

- `core`：`name`（1–8 字）、`origin`、`aptitude`、`language`（受控词表）、`obsession`、`wound`、`voice`。
- PoW：`sha256(stableStringify({version, core, nonce}))` 的前 `difficulty` 个十六进制位必须是 0。默认 3（平均约 4096 次哈希），用 `ARRIVAL_DIFFICULTY` 调整，多节点必须一致。
- 记录由上传所在节点的 Ed25519 私钥签名；不是权威时，节点把签名记录 `POST /api/arrival/publish` 转发给当前权威，请求本身也走节点签名。
- 引擎在 `applyArrival` 里做落点、重名、受控词表校验；落点是确定性扫描，重放和追平后每个人的位置与属性一致。
- 隐私红线：上传前明确提示“日志只追加、不可删除”；服务端拒绝网址、邮箱、账号（`@handle`）和 8 位以上数字串。这是正则过滤，不是人工审核。
- “只上传一次”是双层的：创建者节点级（日志里已有该 `nodeId` 的 `arrival` → 409，`ARRIVAL_ONCE_PER_NODE=0` 可关）+ 浏览器 `playerId` 级（同一个玩家 id → 409）。旧记录可以没有 `playerId`；清掉 localStorage 就能换一个玩家 id，所以节点级仍是硬限制。
- 举报：`POST /api/report {agentId, reason}` 只写本机 `REPORT_FILE`（默认 `reports-<节点名>.json`，已 gitignore），供人工查看；`GET /api/reports` 返回每个居民被举报的次数。举报内容不进共享日志。

## 在线轴 v2：主人的模型

上传者的节点（`arrivedBy` 的那个 `nodeId`）每隔 `OWNER_INTENT_INTERVAL_MS`（默认 2000）替自己的居民想一个动作：

- 有 API Key 时用主人配置的模型（`decideForOwner`），否则用规则；`mockDecide` 会保存并恢复世界 RNG，避免“提议”变成一次没写进日志的随机数消耗。
- `POST /api/intent { agentId, action, basedOnTick }`，请求由节点 Ed25519 签名。
- 权威检查 `agent.arrivedBy === 请求节点`，再用 `sanitizeAction` 把动作重新过一遍受控解析；非法动作 400，不是主人 403。
- 合法动作进内存队列；到这个人下一次真正要决策时，`processBrains` 取出来写成 `decision` 事件（`source: owner`），`rngAfter` 记录当时的 RNG。重放只看这条决策，不再需要提案。
- 提案到达时顺手续上 `presence` 清醒租约（`reason: owner-online`，长度 `OWNER_LEASE_TICKS`，默认 60），所以主人在线的人不会淡出。
- 主人在线但这一拍没有提案时，权威写一条 `source: owner-wait` 的 `idle` 决策，让居民等着，而不是被规则接手。等待本身也进日志，重放时所有节点做出同样的等待。
- 提案超过 8 秒、或落后超过 40 tick 会作废；主人租约到期后（不再有 `/api/intent`）才退回规则。
- 观看者在跟随节点上的守望会由该节点转发给权威（`/api/presence/forward`），不再要求观看者连到权威本机。
- 浅睡（`POST /api/shallow`）给自己的居民买一个 `SHALLOW_LEASE_TICKS`（默认 1 个世界日）的在线保护：不淡出，但主人循环会避开浅睡中的居民，权威按规则驾驶；租约到期自动回到规则。v1 不接支付。

## 接入你自己的模型

支持两种接口：**OpenAI 兼容** 与 **Anthropic 兼容**。

在右侧「大脑」里填：

- **接口类型**：OpenAI 兼容 / Anthropic 兼容
- **API 地址**：例如 `https://api.deepseek.com/v1` 或 `http://10.254.40.145`
- **API Key**：只保存在运行中的进程内存里，不写入磁盘、不回传到浏览器。
- **模型名**：例如 `deepseek-chat`、`deepseek-flash[1m]`
- **用 LLM 的人数**：0–12。

也可以完全用环境变量启动，不把 key 写进任何文件：

```bash
LLM_PROVIDER=anthropic \
LLM_BASE=http://10.254.40.145 \
LLM_KEY=你的key \
LLM_MODEL='deepseek-flash[1m]' \
LLM_AGENTS=12 \
node server.js
```

不配置时，世界照常运行——这让它可以被任何人打开、观看、演示。
