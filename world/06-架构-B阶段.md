# 架构约束 · B 阶段：无中心节点

> 状态：已确认（2026-11-03）；故障交接、节点身份签名、分区演练与 TLS 端到端验证已落地（2026-11-04）。这一页只锁定约束，不写具体实现。
> 依据：[03-设定集-最后的岛.md](03-设定集-最后的岛.md) 第 9、11 节；[05-开发进度.md](05-开发进度.md)。
> 当前可跑的演示版见 tag `demo-mirror`。

## 0. 北极星

- **没有官方服务器**。每个观看者运行自己的全节点。
- 世界状态 = 所有人重放同一份事件日志；同一份种子 + 同一份日志 ⇒ 同一个世界。
- 节点可轮换排序；只要还有一个人保存日志，世界就还在。
- 密钥、模型、叙事缓存只在玩家本机。
- “无服务器”不等于没有进程：本机的 `node server.js` 就是节点，不是中心。

## 1. 明确不做

- 不做中心 API、中心存档、中心账号。
- 不让任何单一节点成为永久权威。
- 不在“单主 → 镜像”的假设上继续加功能。
- 不让模型决定事实、生死、胜负；模型只提案和说话。
- v1 不做拜占庭容错，只做可验证的诚实节点与确定性收敛。

## 2. 权威（Authority）

- 事件日志**只追加、不修改**；状态只是日志的投影。
- 本地存档只是缓存，丢了可以从日志重建；权威永远在日志。
- 事件至少带：协议版本、发起节点、term、seq、tick、type、payload、prevHash、签名。
  （v1 的签名落在信封上：一段日志整体由发送节点用 Ed25519 签名，并通过 `prevHash` 与前后块成链；逐事件签名留给后续。）
- 引擎是唯一的事实判定者；模型提交 intent，引擎写 result。
- 每个节点都能独立重放与校验；状态哈希不一致就是分叉，**必须停下来**，不能静默采用。
- 观看者的叙事缓存、密钥、模型配置不进日志、不参与同步。

## 3. 排序（Ordering）

- v1 采用**轮值日志权威**：同一 term 内只有一个节点可以写总账，其他人只能提案。
- term 轮换：按节点列表轮转或租约到期触发；新 term 必须从旧 term 的 head 延伸。
- 冲突：以更高 term 为准；同一 term 出现分叉视为故障，拒绝合并并要求人工处理。
- 旧主回归：先同步到当前 head，再按轮次重新参与，不自动复位。
- 排序只依赖日志字段（term / seq / prevHash / 节点 id），不依赖墙钟、模型输出或网络到达顺序。
- 排序节点失联时，下一步是“明确的租约过期 + 下一节点接手”，不是随意抢写。
  （已落地：交接本身写成日志里的 `term` 事件；墙钟只用于判断失联时长，排序只看日志字段。）

## 4. 创建（Creation）

- 新居民只有一个入口：`arrival` 事件。没有中心创建 API。
- `arrival` v1 已落地（2026-11-04）：四字段（出身 / 执念 / 禀赋 / 旧伤）、一句口吻、语言、创建者 Ed25519 签名、轻量 PoW。上传在本机构造并签名；不是当前权威时，通过节点签名请求转发给权威。引擎校验受控词表、重名、落点与重放一致性；违规事件直接拒绝。
- genesis 必须全网一致。当前**仍采用 B**，`arrival` 落地后已具备切到 A 的条件，但尚未启用：
  - **A. 空世界**：第一个人通过 `arrival` 进入（正式上线目标）；
  - **B. 确定性初始居民**：所有节点从同一个 seed 算出同一批人（当前 12 人，现阶段采用）。
- 隐私红线 v1：上传前明确告知“日志不可删除”；服务端用正则拒绝网址、邮箱、账号与 8 位以上数字串。这是过滤，不是人工审核。
- “只上传一次”v1 以创建者节点为代理：日志里已有该 `nodeId` 的 `arrival` 时拒绝后续上传（`ARRIVAL_ONCE_PER_NODE=0` 可关闭）。仍缺按人而非按节点的一次性、举报/审核入口、自述与真实身份的隔离。PoW 只抬高成本，不防有算力的刷子。

## 5. 模块边界

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `engine.js` | 确定性模拟、事实判定、事件写入 | 不碰网络、密钥、模型 |
| `sync.js` | 日志信封、校验、重放、追平 | 不决定谁是权威 |
| `identity.js` | 节点密钥、信封/请求签名、防重放、信任表 | 不解释世界、不判定事实、不决定排序 |
| `arrival.js` | 上传的 PoW、创建者签名与校验 | 不决定落点、属性或重名（那是引擎） |
| `transport`（在 `server.js` 内） | 在节点间搬运签名日志块 | 不解释世界、不判定事实 |
| `server.js` | 本机节点守护 + 观看界面 | 不是官方服务器 |
| 观看者模型 | 本机生成叙事、决定 intent | 结果不得写回事实层 |

## 6. 当前状态与迁移

- 现在：`SYNC_MODE=peer` 已落地（2026-11-03）。双向拉缺失日志；`term` 由事件数决定；交接先拉后写；同头不同哈希即 `syncFault`。
- 故障交接已落地（2026-11-04）：权威失联超过 `TAKEOVER_MS` 后，下一个节点把交接写成日志里的 `term` 事件并接任；旧权威回归读到更高任期后只读；旧尾巴比幸存者新时以更高任期重建；同任期分叉仍停写，`/api/sync/adopt` 提供人工出口。
- 节点身份签名已落地（2026-11-04）：每个节点持有 Ed25519 密钥；日志信封、身份声明、写入请求都签名；首次接触按 TOFU 固定公钥，换钥匙/换节点名即拒绝；写入请求带时间戳与 nonce 防重放；`SYNC_TOKEN` 仍可作为过渡授权。可选 TLS 已接入。
- 验收与故障演练已落地（2026-11-04）：`peer-check.js` 做跨机器只读对账；`test-partition.js` 用可切断 TCP 代理验证分裂、愈合、旧尾巴丢弃与人工 `/api/sync/adopt` 恢复；`test-tls.js` 用自签证书验证 HTTPS 双节点收敛。分区愈合仍是有损的：更高任期为准，旧权威分区期间的事件被丢弃，并记录在 `lastAdoption.dropped`。
- 不静默丢弃（2026-11-04）：节点记录本进程启动时的日志头；如果愈合会丢弃“启动后写过”的事件，就停写并要求人工 `/api/sync/adopt`，不再自动采纳。崩溃重启带回来的旧尾巴仍自动采纳。`force: true` 提供日志全量重新引导入口。
- 在线与上传 v1 已落地（2026-11-04）：观看者守望写成日志里的 `presence` 租约；四字段上传写成 `arrival` 事件，带 PoW 与创建者签名，支持跨节点转发。两者都按原序号重放，`stateHash` 覆盖 `presence` / `presenceUntil` 与新增居民。
- 在线轴 v2/v3 已落地（2026-11-04）：居民的主人节点（`arrivedBy`）可以签名提交 `intent`，权威校验归属并重新做受控解析，到决策拍写成 `source: owner` 的 `decision` 事件；主人在线无提案时写 `source: owner-wait` 的等待决策（也进日志，重放一致）；主人租约到期后才退回规则。跟随节点上的观看者守望通过 `/api/presence/forward` 转发给权威。修掉了“块尾是 term/presence/arrival 时 `applyChunk` 误报 stateHash 不一致”的同步 bug。
- 浅睡机制已落地（2026-11-04）：`/api/shallow` 给自己的居民买一个 `SHALLOW_LEASE_TICKS`（默认一个世界日）的在线保护；浅睡期间不淡出、规则驾驶、主人循环避开，租约到期自动回到规则。真实收费未接。
- 尚未启用：空世界 genesis（A）。当前仍从 seed 生成 12 个初始居民，`arrival` 在其后追加。
- 保留：`MIRROR=1` 的单主 → 镜像模式只作演示与回归，不再是主路径。
- 不新建文件夹或仓库；原地替换同步层，复用 engine / sync / UI / 测试。
- 已验收：两个真实进程轮流担任排序节点，各自产生事件，互相校验后状态哈希收敛；杀掉当前权威后幸存者接任、旧权威重启后收敛为跟随者；旧权威存档领先时按更高任期重建且不报 `syncFault`。
- 未完成：网络分区（非宕机失联）后的**无损**自动合并（当前按更高任期重建会丢弃旧尾巴，人工确认后才能采纳）、写冲突自动仲裁、拜占庭容错、自动全量重新引导（`force` 是人工入口）。首次信任仍是 TOFU，不能替代带外公钥核对；TLS 已端到端验证，但证书轮换与吊销未做。

## 7. 开放问题

- 节点身份与密钥管理：已用 Ed25519 + 本机密钥文件绑定节点名，首次信任用 TOFU；仍缺带外核对公钥指纹的流程、密钥轮换与吊销。
- 任期长度、轮换触发条件、失联判定与租约续期。
- 传输：HTTP 轮询之外是否需要 WebRTC / libp2p；NAT 穿透与消息大小上限。
- 在线状态：v1 把观看者的守望写成日志里的 `presence` 租约；v2/v3 让主人节点通过签名 `intent` 驱动自己的居民，主人在线无提案时权威写 `owner-wait` 等待，跟随节点的守望也能转发。仍缺付费浅睡与“在线才说话、离线是哑者”的行为差异；主人租约（默认 60 tick）需要根据真实网络继续调。
- 日志存储：全节点长期保存的代价；是否允许裁剪，裁剪后如何重建。
- `arrival` 的 PoW 难度、防刷与隐私红线的具体数字：v1 默认难度 3（平均约 4096 次哈希），隐私用正则过滤；防止有算力的刷子、一人一次、举报/审核仍待定。
- 观看者叙事是否参与同步（当前结论：不参与，只在本机缓存）。

## 8. 失败信号

- 代码里又出现一个“官方服务器”或中心存档。
- 两个节点的 `stateHash` 不一致却继续运行。
- 用模型输出决定排序、事实或生死。
- 为了赶功能，把镜像模式当成最终形态。
- 新增功能绕过了事件日志（直接改状态、直接改别人的存档）。
