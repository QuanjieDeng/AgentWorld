## 2. 现在能跑什么

```bash
cd world/prototype
node server.js          # http://localhost:4173
npm test                # 140 个测试
node test-sim.js        # 5 个种子 × 2.5 个世界日
node test-cycles.js     # 资源循环
node sync-check.js journal.json   # 用另一台机器导出的日志校验并重建世界
node peer-check.js http://A:4173 http://B:4173 --watch 30 --settle   # 两台机器对账
```

- 零依赖，`npm install` 不需要。
- 每 10 秒自动存档；重启后按离线时间快进，并给出关键事件摘要。
- 不配置模型时，规则大脑照常运行；配置后 LLM 只提交意图，引擎判定结果。
- 事件日志为权威，决策可重放；可从种子 + 决策日志重建世界。
- 观看者状态里同时有 `facts`、每个居民的 `beliefs`、`chronicle`、`remains`。
- 页面上的时间轴与编年史走本地 API（`/api/timeline`、`/api/chronicle`）；不配置模型时用本地叙事器。
- 事件日志可导出成带哈希的信封（`/api/journal`）；`SYNC_MODE=peer` 下每个节点双向拉取缺失日志，按事件数轮换写入权，权威失联后由下一个节点按租约到期接任；`/api/identity` 可看角色、任期、继任者、接管倒计时、`syncFault` 与节点公钥。单主/镜像模式仍可用于演示。
- 每个节点首次启动生成 Ed25519 身份；日志信封、身份声明和写入请求都签名，对端按 TOFU 固定公钥，写入请求带时间戳与 nonce 防重放。可选用 `TLS_KEY_FILE` / `TLS_CERT_FILE` 开 HTTPS；`peer-check.js` 可在两台机器之间核对身份、信任、签名与收敛。
- 跟随一个人就是守望他：页面心跳让当前权威写 `presence` 租约，被守望的人醒着、不参与淡出；心跳消失或切走就回到规则驾驶。`presence` 进事件日志，重放、追平后所有节点判断一致。
- 右上角「上传一个人」：填四字段 + 一句口吻 + 语言，浏览器算轻量 PoW，本机节点签名后写 `arrival` 事件；不是权威时自动转发给当前权威。受控词表、重名、隐私正则都在引擎/入口校验，重放后落点与属性一致。
- 主人节点的模型：上传者所在的节点每隔几秒替自己的居民算好下一步，签名后交给当前权威；权威检查归属、重新做受控解析，到决策拍写成 `source: owner` 的决策；提案顺带续上清醒租约。主人在线但这一拍没有提案时写 `owner-wait` 发呆等待，租约过期后才退回规则。观看者挂在跟随节点时，守望会转发给当前权威。
- 浅睡：自己的居民可以买一个世界日的半离线保护；不淡出、规则驾驶，租约到期自动醒来。v1 只做机制，支付是外部闸门。
- 保管凭证（占位）：配置 `CUSTODY_TOKEN` 后，`/api/custody` 可以给居民买最长 365 天的在线保护；真实支付未接。
- 实验信念大脑：`BELIEF_RULES=1` 让规则大脑在判断威胁时读自己的信念（被谁打过、听说谁杀过人），默认关闭；决策仍写日志，重放一致。
- 临终脱变：死前不足 2 次的人会完成 `last_days` / `deathbed` 脱变，标签只由 id 决定，重放一致。
- 英文世界文本：配了模型时 `/api/translate` 会把编年史叙事按需翻成英文并缓存；没配模型时原文返回。
- 公开侧：全岛面板有「改变过的人」「从雾里来的人」；编年史可以导出 Markdown；居民可以被本机举报（不进共享日志）；`/public` 进入只读看台，右上角可切中/英文界面外壳。
- 时间轴回到过去：选过去的第 N 天，`/api/history?day=N` 从日志重放到那天 08:00，页面切到只读历史态，能看到当时的地图、居民、建筑和野兽；点「今天」回到现在。
- 叙事缓存：按「观看者 + 事件段 + digest」缓存在本机 `narratives-<节点>.json`，重启后同一段事实不必重新调用模型；只在本机，不跨节点同步。
- 分区保护：本进程启动后写过的事件如果在愈合时会被静默丢弃，节点就停写并提示 `/api/sync/adopt`，不再自动吞掉；`force: true` 可做日志全量重新引导。

**B 阶段全节点轮值同步已完成（主路径）**：`SYNC_MODE=peer` 下每个节点双向拉取缺失日志，`term` 由事件数决定，同一时刻只有当前权威推进模拟；交接时先拉完日志再写。两个真实服务进程的集成测试验证了双方轮流担任权威、每个任期后状态哈希收敛；单主/镜像保留为演示/回归模式。

**B 阶段故障交接已完成**：权威失联超过 `TAKEOVER_MS` 后，轮值里的下一个节点把 `{term, authorityId, reason}` 作为 `term` 事件追加进日志并接任。排序仍然只看日志字段（term / seq / prevHash / 节点 id），墙钟只用于判断“失联多久”。旧权威带着旧存档回来时会读到更高任期，先追平、再作为跟随者参与；如果它的存档比幸存者更新（失联前最后几条事件没人拉到），以更高任期为准重建并丢弃那段旧尾巴。同一任期内真正分叉仍然记录 `syncFault` 并停写，可用 `/api/sync/adopt` 人工指定基准。集成测试覆盖：杀掉当前权威→幸存者接任并继续推进→旧权威重启后只读；以及旧权威存档领先时的重建路径。

**B 阶段节点身份签名已完成**：每个节点首次启动生成 Ed25519 密钥对，私钥只在本机文件里（`NODE_KEY_FILE`），不进存档和日志。`/api/journal` 的每个信封、`/api/identity` 的每次身份声明都由本节点签名；对端第一次接触时把公钥固定进本机信任表（`TRUST_FILE`），之后换钥匙、或同一地址换节点名都会被拒绝。`/api/journal/apply` 与 `/api/sync/adopt` 接受 token 或带 `timestamp` + `nonce` 的节点签名；服务端先验签再记录 nonce，时钟窗口默认 60 秒、nonce 保留 5 分钟，原样重放会被拒绝。日志签名者和请求签名者必须是同一节点，否则返回 403。可选 TLS 已接入（`TLS_KEY_FILE` / `TLS_CERT_FILE`）。首次信任仍是 TOFU，首次 MITM 要靠 TLS + 带外核对公钥指纹解决。

**B 阶段验收与故障演练已完成**：`peer-check.js` 是跨机器的只读对账工具，检查身份自证、种子、互相固定的公钥、日志信封签名，`--watch` 记录任期/写入权轮换，`--settle` 暂停当前权威后确认 `stateHash` 收敛。`test-partition.js` 用两个可切断的 TCP 代理夹住两个真实进程：断网后两边同时持有写入权；愈合后以更高任期为准，旧权威丢弃分区期间写的事件（`/api/identity.lastAdoption.dropped`），另一侧记录 `syncFault` 并停写；人工 `/api/sync/adopt` 后恢复并继续推进。`test-tls.js` 运行时生成自签证书，验证两个 HTTPS 节点在签名身份下收敛。两台真实机器的手动验收清单写在 `prototype/README.md`。

**B 阶段在线/睡眠轴 v1 已完成**：观看者跟随某个人时，页面每 5 秒发一次守望心跳；当前日志权威把活跃心跳翻译成日志里的 `presence` 事件（带 `untilTick` 的清醒租约）。被守望的人 `presence='online'`，不参与每日遗忘；心跳消失、切走或租约到期后回到规则驾驶。`presence` 是事件日志的一部分，重放、追平、重建后所有节点对“谁醒着”的判断一致；`stateHash` 覆盖 `presence` / `presenceUntil`。观看界面显示“醒着 · 有人守着 / 睡着 · 本能”。v1 只在权威本机生效，且只影响清醒/淡出，不改变说话与行动方式——那要等真人上传与模型归属。

**B 阶段上传 / `arrival` v1 已完成**：新居民唯一的入口是 `arrival` 事件。表单提交四字段（出身 / 执念 / 禀赋 / 旧伤）+ 一句口吻 + 一种语言；出身、禀赋、语言只接受引擎里的受控词表，执念/旧伤/口吻有长度与隐私正则（网址 / 邮箱 / 账号 / 8 位以上数字）校验。浏览器用 SHA-256 算前 N 个十六进制 0 的轻量 PoW（默认 3，`ARRIVAL_DIFFICULTY` 可调，多节点必须一致）。上传所在节点用自己的 Ed25519 私钥签记录；不是当前权威时，把签名记录通过 `/api/arrival/publish` 转发给权威，请求本身也走节点签名。引擎负责重名、落点（确定性扫描中心空地）与属性生成；`arrival` 事件像 `presence` 一样按原序号重放和追平。“只上传一次”以创建者节点为代理：日志里已有来自该 `nodeId` 的 `arrival` 时，后续上传被 409 拒绝（`ARRIVAL_ONCE_PER_NODE=0` 可关闭）。隐私红线是正则过滤而不是人工审核。

**B 阶段在线轴 v2 已完成（主人提案）**：`arrivedBy` 就是居民的主人节点。主人节点每隔 `OWNER_INTENT_INTERVAL_MS` 替自己的居民算好下一步（有 API Key 用主人的模型，否则用规则），签名后 `POST /api/intent` 给当前权威。权威检查 `agent.arrivedBy === 请求节点`，用 `sanitizeAction` 把动作重新过一遍受控解析（不是主人 403，非法动作 400），合法动作进内存队列；到这个人下一次真正要决策时，`processBrains` 取出来写成 `source: owner` 的 `decision` 事件，`rngAfter` 记录当时的 RNG，重放只看这条决策。提案到达时顺手续上 `presence` 清醒租约（`reason: owner-online`，长度 `OWNER_LEASE_TICKS`）。主人在线但这一拍没有提案时，权威写一条 `source: owner-wait` 的 `idle` 决策让居民等待，等待本身也进日志，重放时所有节点做同样的等待；提案超过 8 秒或落后超过 40 tick 作废，主人租约到期后才退回规则。观看者挂在跟随节点时，节点用 `/api/presence/forward` 把守望转发给当前权威，权威按 `${nodeId}:${viewerId}` 记住并写 `presence`，心跳停止或节点掉线后由 TTL 清理。`mockDecide` 在主人节点上保存并恢复世界 RNG，避免“提议”变成一次没写进日志的随机数消耗。做这一步时还修掉一个同步 bug：块尾是 `term` / `presence` / `arrival` 时，`applyChunk` 现在会在比较 `stateHash` 前先收尾插入，否则单条非决策事件的块永远对不上。

**分区不再静默丢弃**：节点记录本进程启动时的日志头；如果愈合时更高任期会丢弃“启动后写过”的事件，`adoptPeerJournal` 不再自动采纳，而是停写并提示人工 `/api/sync/adopt`。崩溃重启后从存档带回来的旧尾巴（启动前写入）仍然自动采纳，所以故障交接行为不变。`/api/sync/adopt` 新增 `force: true` / `rebootstrap: true`，允许从任意可信节点全量重建，用于日志损坏时的重新引导。

**浅睡与公开侧 v1**：`/api/shallow` 给自己的居民买一个 `SHALLOW_LEASE_TICKS`（默认一个世界日）的在线保护；浅睡期间 `presence` 在线、不淡出，但主人循环会跳过它，权威按规则驾驶，租约到期确定性地回到离线。跟随节点可以把浅睡请求转发给权威。全岛面板新增「改变过的人」「从雾里来的人」；编年史可以导出本机版本的 Markdown；`/api/report` 把举报写在本机 `REPORT_FILE`，供人工查看，不进共享日志。上传的“一次”现在是节点级 + 浏览器 `playerId` 级双层限制。`/public` 或 `/?public=1` 是只读看台，隐藏暂停、倍速、上传、大脑、写信、浅睡和举报；右上角可以切中/英文界面外壳（`?lang=en`，localStorage 记住选择），但居民对话、编年史叙事、制度描述等世界文本仍是中文。

**时间轴可以真正回到过去**：`/api/history?day=N` 把当前日志重放到第 N 天 08:00，返回当时的 `snapshot`（地图、居民、建筑、野兽、制度、日志）；页面切到只读历史态，地图和面板都显示那一天的状态，点「今天」恢复实时流。历史快照按天缓存在进程内，世界被整体重建时清空。它依赖完整的 `arrival` / `presence` / `term` 重放，所以之前那几层的确定性修复是前提。

**实验规则与收尾**：`BELIEF_RULES=1` 开启后，规则大脑在判断“谁是威胁”时会读自己的信念（被谁打过、听说谁杀过人），而不是全知的世界关系；默认关闭，避免改变现有可玩性，决策仍写成 `decision` 事件，重放一致。脱变下限 2 次用临终脱变补足：死前不足 2 次的人依次获得 `last_days` / `deathbed`，标签由 id 决定、不消耗 RNG。`/api/custody` 是保管支付的占位：配置 `CUSTODY_TOKEN` 后可给居民买最长 365 天的在线保护，真实产品应换成支付服务签名的收据。`/api/translate` 在配置模型时按需翻译编年史叙事并缓存在本机；没配置模型时原文返回。

## 5. 模拟里已经能看到什么

近几次 `test-sim.js`（2.5 个世界日、5 个种子）的观察：

- 居民会因为饥饿、仇恨或野兽死亡；会出现人与人之间的冲突与凶杀。
- 收养与继承会发生；无人继承时留下遗产与空宅，后来者会搬进去。
- 脱变每局出现 3–6 次，包括“仇人死亡”“杀人后活下来”“被别人当成主心骨”。
- 制度会自己长出来：每局出现律法、教义，部分局还会出现结社。
- 语言墙生效：约一半交谈互相听不懂；2.5 天后有 3–5 人学会第二语言，另有 3–6 次明确的语言教学。
- 谣言会沿信念链漂移，但事实层逐字节不变。
- 较长的局里，长期无人提起的人“被记住”程度会降到个位数，逼近淡出；社交活跃的人保持在 40–100。

## 6. 已知缺口（明确推迟，不是遗忘）

1. **规则大脑默认仍是全知的**：`BELIEF_RULES=1` 已能按自己的信念判断威胁，但默认关闭，且只覆盖“被谁打过 / 听说谁杀过人”，其余行为仍读世界状态。规格第 30 条“按信念行动”完成了一半多一点；LLM 提示词里已经带信念。
2. **脱变下限 2 次已用临终脱变补足**：死前不足 2 次的人会获得 `last_days` / `deathbed`；标签是确定性的，不是模型选的。上限仍是 2–5。
3. **LLM 脱变标签现在会随日志重放**：标签写在 `turning` 事件里，重放时优先读它，不再退回确定性标签；但它不是带序号的决策记录，两台机器同时触发同一场脱变时谁先仍未定义。
4. **语言是模拟的**：三种语言用 ID + 中文文本表示，没有真正的陌生语言生成与客户端翻译层；观看者“看得懂”是设定层实现。
5. **知识教学不要求共享语言**：当作手势与示范处理，是为可玩性做的简化。
6. **祖先的声音只按“是否在关系链里”设限**，不是严格血统；玩家属于哪条血脉的身份模型还没有。
7. **离线推进有上限**：默认最多补 7 个世界日（`OFFLINE_MAX_DAYS` 可调）；超出部分只报告 `skippedTicks`，不模拟也不保留关键事件。
8. **轮值同步还不是生产级协议**：双向拉取、按事件数轮值、交接先拉后写、租约到期接管、旧权威隔离、节点身份签名、TLS 端到端测试、分区演练与“不静默丢弃”保护已完成；分区愈合仍是有损的——以更高任期为准，人工确认后旧权威分区期间的写入会被丢弃（记录在 `lastAdoption.dropped`），停写的一侧需要 `/api/sync/adopt`。`force: true` 可以做日志全量重新引导。自动冲突仲裁、拜占庭容错仍未实现。首次接触仍靠 TOFU，公网部署必须配 TLS 并带外核对公钥指纹。
9. **在线/睡眠轴完成到 v3 + 浅睡 + 保管凭证占位，但还不是完整的“清醒/哑者”分离**：守望租约、确定性重放、在线不淡出、主人提案、`source: owner` / `owner-wait` 决策、守望转发、浅睡、保管凭证都已完成；仍缺真实收费（凭证是共享 token 占位）、审核流程、以及“在线才说话、离线是哑者”的行为差异（离线居民目前仍有规则对话，为了语言系统可玩）。主人租约默认 60 tick，主人掉线后要等租约过期才恢复规则。制度已经可用，但条目仍有限：律法只针对攻击，教义仪式只实现两种，争抢解释权用声望与结社权重近似，没有直接冲突。
10. **历史态回放已完成，但只在进程内按天缓存**：`/api/history?day=N` 能把地图和每个人的状态倒回那一天；很远的过去或长日志会慢，快照不跨节点、重启后重算。更细粒度的时刻（任意 tick）还没有 UI 入口。
11. **叙事缓存已跨进程保留，但仍只在本机**：`narratives-<节点>.json`，重启后同一段事实直接复用；不同观看者的版本靠 id 隔离，不跨机器同步，也没有批量导入/导出（单天 Markdown 导出已有）。
12. **真人上传 v2 已落地，但还不是正式创建流程**：受控字段、轻量 PoW、创建者签名、隐私正则、确定性落点、跨节点转发、节点级 + 浏览器 `playerId` 级一次性、本机举报计数已完成；仍缺真正的身份绑定（清掉 localStorage 就能换玩家 id）、审核流程与申诉、自述与真实身份的隔离、以及 P2P（当前仍是 HTTP 轮询）。PoW 只抬高刷量成本，防不住有算力的刷子。
13. **英文完成到「界面外壳 + 编年史按需翻译」**：`?lang=en` 翻译标签与状态；配了模型时 `/api/translate` 会把编年史叙事翻成英文并缓存。居民对话、制度描述、事件文本仍是中文；真正的双语世界需要更完整的翻译层。`/public` 只读看台与界面语言切换已完成。

## 7. 建议的下一步

架构约束已锁定在 [06-架构-B阶段.md](06-架构-B阶段.md)，peer 轮值、故障交接、身份签名、分区演练、TLS 与在线轴 v1 已落地。接下来：

1. **两台真实机器手验（仍需人工）**：照 `prototype/README.md` 启动 A、B，跑 `peer-check.js --watch 30 --settle`；再杀权威、重启旧节点、断网分区，按清单逐项确认。自动化双进程只能证明协议逻辑，不能代替真实网络与真实证书。
2. **在线轴 v4**：等待提案、守望转发、浅睡、保管凭证占位已经能用。下一步把凭证换成真实支付收据、做“在线才说话、离线是哑者”的行为差异，并把主人租约/提案过期做成界面上更细的状态。
3. **上传 v3**：把玩家 id 绑定到真实身份（现在是浏览器 localStorage）、审核与申诉流程、自述与真实身份的隔离；PoW 难度与防刷数字需要重新评估。
4. **公开看台 v2**：只读看台、英文界面外壳与编年史按需翻译已经能用；下一步做英文世界文本（对话/制度/事件）、名人录 permalink、编年史分享链接。
5. **协议硬化（可并行）**：分区后的无损自动合并、写冲突自动仲裁；日志全量重新引导已有 `force` 入口。拜占庭容错明确不在 v1。
6. **实验开关评估**：跑几局 `BELIEF_RULES=1`，观察冲突与误判的分布，再决定是否默认开启。现在默认关闭。

最后才是存续订阅与代写一生。
